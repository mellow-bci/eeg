# Raw training to durable inference restart

Comparison harness only, not live production training or observed Cortex parity. No vendor assets required or accessed.

`ReferenceRawTrainingWorkflow.prepare` collects explicit labeled raw-block trials through `ReferenceRawMentalWorkflow` and sends only clean processed features to `ReferenceClassifierRebuild.acceptTraining`. This invokes existing epoch assembly, Gaussian training bank, feature ranking, PCA/canonical fitting and profile-property acceptance. Each trial starts its own filter/window/background state: an independent experiment boundary, not a recovered vendor lifecycle rule. Caller explicitly supplies all epoch tick invocations, quality, timestamps, recipe, labels, fitting/resource limits and channel metadata.

The in-memory classifier property callback performs a real local assignment and acknowledges that assignment only. Vendor lifecycle requests, especially eligible brain-map updates, are returned as deferred operations. No brain-map output or lifecycle parity is invented. See `../training-save-orchestration-20261011/TRACE.md`: the vendor property acknowledgment is not a durable write receipt.

`save` separately requires a successfully fitted classifier and uses the real `ReferenceLocalProfileStore` SQLite transaction + owned AES-GCM envelope. Encryption key is supplied to the store, never embedded by the workflow. Errors propagate; a precommit injected failure cannot return a revision. The store distinguishes committed-but-unacknowledged outcomes.

Metadata contains independent schema version 1, algorithm version, caller provenance, complete numeric raw recipe and an explicit true training-bank-durable flag. Reopen requires exact recipe and algorithm-version agreement before constructing raw inference. The same encrypted SQLite payload now includes collected epoch/timestamp rows and typed class Gaussian distributions. Reopening a trainer validates bounds, IDs, dimensions, finite values, timestamps, channel metadata, recipe and schema before accepting additional training. Bank and classifier persistence are one atomic owned transaction; this does not claim vendor transaction semantics. Neutral-bank preservation and changed model/density after action retraining at revision 2 are tested. This supports bounded independent retraining restart, not vendor cache/history/brain-map lifecycle parity.

Tests collect 40 authored raw epochs for neutral and one action, fit from the actual processed features, save, close, reopen and compare raw replay predictions. Additional checks reject changed recipe/version, expose precommit failure with no saved record, and reject insufficient four-epoch fitting without durable success. Authored waveforms are not participant recordings, and replay matching does not prove physiological command validity or external Cortex equivalence. Initial coordinator combined run found four failures in these two tests. Diagnostic failureDescription identified emptyPCASelection: the authored globally scaled waveforms concentrated over 99% of variance into their first component, correctly triggering the existing traced PCA empty-selection gate. The fixture now varies channel amplitudes more independently and uses a smaller class offset; no fitting gate or implementation math was changed. Both tests then passed with `swift test --package-path apple --filter ReferenceRawTrainingWorkflowTests` (2 tests, 0 failures). Initial combined failure, focused diagnosis and passing focused log are retained alongside this note. Coordinator owns final broader verification.

Final focused run after bounds coverage: 3 tests, 0 failures (`focused-bounds-tests.log`). Collection caps accepted epochs/cells before appending and requires nondecreasing timestamps (equal timestamps allowed). Malformed owned bank IDs/shapes, decode byte/epoch limits, changed training channel metadata, reversed timestamps and excess collection all reject.

## Optional timed lifecycle composition

`Timing` supplies the existing lifecycle configuration, independent monotonic collection clocks and explicit acceptance clocks plus scoring histories. Recipe sample/step must agree with lifecycle sample/step; no wall clock is inferred from stored epoch timestamps. Timed mode passes each available processed frame through `advance(control:1)`, then invokes actual accept/refit from `advance(control:2)`'s fit callback. Insufficient collection raises an explicit lifecycle rejection with event/count, without fitting or saving. Collected transitions remain inspectable. Configuration and supplied clocks are retained in owned provenance. No resetAction/brain-map operation is claimed by this collect/accept-only path.

Direct mode remains intentionally labelled `independent-reviewed-epochs`; it is not described as vendor timed collection. Both paths reuse identical feature and fitting kernels. Each trial starts a separate experiment state; persisted bank supports later refit, not mid-trial timer resume.

Focused timed test uses explicitly supplied recovered delay 1s, duration 8s, minimum 12 and maximum 100 with compatible 64Hz/16-sample step. It confirms 28 appended epochs, delay boundary, completion event2 and acceptance event4 feeding a real fit. A separately advanced wall clock reaches the cap before enough epochs, yielding event7 and no acceptance. Final focused run: 4 tests, 0 failures (`focused-timed-tests.log`).
