# Training persistence wrapper evidence

Installed CortexService arm64 SHA-256 `cdb5083641488056ceacfb8f2a0a0db724c8ce50585fd48aecbdcd1d179f936a`. Static captures only. No vendor serializer, database encryption, credentials, binaries or trained assets added. `ReferenceTrainingDatabase` is a typed in-memory contract; callers supply independent values and own durable storage.

## Gaussian classes

`GaussianDatabase::loadClassesData` at `0x100b417a4` requires profile nonnull and processes requested vector in order. It clears prior output on nonempty input, appends a default GaussianAlgebra per ID, sets its class ID (`0x100b419c4..d0`), and conditionally retrieves the profile payload. Missing data leaves the initialized empty class. Existing data must be convertible to GaussianAlgebra (`0x100b41a04..14`), replaces the entire payload including class ID (`0x100b41a18..54`), and asserts only ID!=−1 (`0x100b41a58..64`). It does not assert stored ID equals requested key. Empty request logs and returns without clearing an existing output; our fresh-result function has no prior output argument and returns an empty vector.

`saveClassesData` at `0x100b41bdc` logs/returns without writing when ID vector empty or ID/payload counts differ (`0x100b41c14..38`). Each incoming payload must have ID!=−1 (`0x100b41d10..18`); the independently requested ID chooses the storage key. The incoming payload ID is not compared to it. With append=false or absent stored key, the new payload is copied. With append=true and present stored key, stored ID remains, incoming GaussianData vector is appended (`0x100b41da4..e38`). The append helper `0x100b40448..470` inserts the source vector at the existing vector end.

If maximum Gaussian count field+8 is zero, no cap. Otherwise, while distribution count exceeds cap, combine first two with false flag (`0x100b41e90..ec8`), assign result over the second (`0x100b41ecc..ed4`), and remove the first (`0x100b41ed8..ee0`). This repeatedly pools the oldest prefix, rather than dropping oldest distributions or ranking by timestamp. Existing `ReferenceGaussianPooling.combine(useFirstUpdateTime:false)` supplies traced count/covariance arithmetic and 32-bit wrap-before-shift timestamp average. Original timestamp values are preserved outside merges; no timestamp generation occurs in these wrappers.

One completed class is passed to EmoProfile::set (`0x100b41f50..70`) before the next class. There is no loop-level transaction/rollback. Conversion errors and invalid IDs are assertion failures, not mock success; `failure-helpers.txt` confirms exact Qt assertion strings at `0x10242152c`, `54c`, `58c`, `5ac`. Our typed boundary represents invalid IDs as errors and cannot receive QVariant type confusion.

## Feature and timestamp matrices

`Database::loadClassesFeatureData` at `0x100b3ed98` processes every requested ID in order, creating aligned empty placeholders in both output vectors (`0x100b3ef98..f0b4`). Keys are `cognitiv-type%1` and `cognitiv-timestamp%1`. Missing keys remain empty independently. Present stored matrices are loaded and transposed (`0x100b3f0b8..148`, `0x100b3f14c..1dc`). No sorting by class ID, timestamp or sample value is shown. Empty input returns without clearing prior outputs; new helper explicitly returns fresh outputs.

`saveClassesFeatureData` at `0x100b3f388` logs/returns without writing if IDs empty or any vector count differs (`0x100b3f3b4..3ec`). For each slot, if either matrix is empty it skips both (`0x100b3f440..45c`). Both are transposed before saving (`0x100b3f544..558`): input rows are feature/timestamp channels, columns epochs; stored rows are epochs. Present matrix is concatenated with new transposed rows using Part=2 (`0x100b3f57c..598`, `0x100b3f5f8..614`); absent matrix is assigned. `append-helpers.txt` shows concatByRow Part2 at `0x102138f68..139018`: previous data copied first, new data appended at its size offset. No deduplication, interpolation, resampling or timestamp monotonicity check is introduced.

Features are set first, timestamps second, then the saved matrices are retrieved and row counts compared (`0x100b3f654..68c`). Mismatch asserts `numOfRecords == savedTimestamp.rows()` via `0x10242146c`; the two prior writes are not rolled back by this wrapper. If configured signed maximum records >0 and row count exceeds it, both matrices keep inclusive range `[count−maximum, count−1]` (`0x100b3f690..6ec`), i.e. the latest appended rows. Nonpositive maximum does not trim. Gaussian maximum is unsigned; our Int argument rejects negative limits as an explicit support policy.

## Independent implementation scope

New `ReferenceTrainingDatabase.swift` uses existing `ReferenceTrainingBank.ClassEntry` and `ReferenceGaussianPooling`, avoiding another Gaussian algebra. Its Store holds Gaussian payloads and persisted feature/timestamp matrices under independent typed class keys. Load methods return fresh ordered results. Save methods return `.ignoredInvalidCounts` for proven count no-ops and commit classes sequentially; failed later operations leave prior writes. Feature row-count failure preserves both newly written matrices.

Finite rectangular-matrix validation and Swift errors instead of process-terminating Qt assertions are our supported-domain choices. Failed rectangular/column validation can occur before a vendor assertion would; those invalid inputs are not parity claims. Pooling remains within the existing bounded kernel's documented supported-feature domain. There is no claimed equivalence to QVariant wire format, Couchbase, encrypted recording storage, profile metadata or cloud durability. No vendor assets are required to implement these wrappers; exact trained-output comparison still separately needs participant-generated parameters and reference predictions.

Five analytic tests are written for request order/missing data/payload identity, append/cap/timestamp arithmetic, logged no-op and partial class writes, matrix orientation/tail retention/skipped slots, and post-write count failure. Tests have not been run in this agent at authoring time: parent requested coordinated builds.
