# Mental-command reference: observed code and unresolved behavior

This is **a bounded static reference study**, not a reimplementation or an equivalence claim. The installed arm64 CortexService on M4 has SHA256 `cdb5083641488056ceacfb8f2a0a0db724c8ce50585fd48aecbdcd1d179f936a`, verified before capture and matching our archived symbol table. Twelve selected ranges were disassembled read-only with LLDB `target create`; no process was attached or launched. No vendor bundle, user classifier or model asset was copied. A separate 32-byte read recovered two coefficient arrays directly referenced by one selected body.

The [manifest](../evidence/mental-command-reference/manifest.json) records addresses, sizes, hashes and commands' bounds. LLDB names four adjacent compiler-generated helpers inside the selected ranges: they are not automatically part of the preceding named routine. Every interpretation below distinguishes named call sites, body instructions and inferences.

canonical-transform argument to the classifier collection count, identifies

## What this establishes

The selected classifier code contains a statistically structured feature-selection/PCA/canonical/Gaussian-density/posterior path, profile-backed neutral training state, headset-indexed sensitivity settings and an explicitly configured score filter. This supports learning from those architecture choices for our independently trained system.

It does **not** establish that each captured routine is used in a particular live headset session, that the entire raw-EEG processing sequence has been recovered, or that we have reproduced mental commands. In particular, `Classification::run` does not directly call the captured preprocessing/Hamming/FFT wrappers, so their position in the end-to-end data path must be traced separately. A plausible diagram is not a recovered call graph.

## Missing parameters and assets

No user profiles, trained Gaussian means/covariances, PCA bases, canonical bases or sensitivity lists were extracted. Their presence as runtime inputs and profile serialization calls is observed; their numeric contents are absent. Static coefficients referenced by the selected score-filter code are the one small exception documented above, and are not a trained model.

Still unresolved: input channel set; sample/window/hop sizes; spectral normalization and band definitions; artifact handling; training/neutral acceptance; regularization; posterior entry meanings; sensitivity mapping; smoothing cadence; decision thresholds; dwell/cancel logic; false-activation rate; cross-session generalization.

## Practical implication for our stack

Keep our verified decoder and immutable raw capture as the acquisition foundation. Treat the reference trace as design evidence for separately implementing explicit windows/features, train-only dimensionality reduction, class/neutral models, transparent smoothing and calibrated rejection. Validate each component on labeled sessions separated from training. Vendor code names or similar architecture cannot replace held-out performance evidence, and missed cue sessions must not be treated as verified training labels.
