# Metadata and independent durable research profiles

This checkpoint traces the installed arm64 CortexService binary rather than README claims. Evidence is in `evidence/mental-command-reference/metadata-schema-continuation-20261011` and `database-driver-continuation-20261011`; binary hash and body addresses are in their TRACE files.

## 1. Metadata schema

`ReferenceTrainingMetadata` covers the ten observed keys: uuid, name, ownerId, deleted, loaded, originalUuid, originalProfileURL, createdDatetime, modifiedDatetime and conditional eegChannels. The channel key is resolved from its actual static initializer, not inferred from a symbol name. Attributes identity JSON contains uuid only; trained attributes are a separate payload.

Strings follow the observed empty projection for missing/non-string values, with diagnostic field names. Native Boolean values are supported; untraced QVariant numeric/string coercions reject. Dates and channel names remain raw strings. Qt date normalization, channel enum lookup and default-channel normalization are unresolved; preserving wire values is our explicit policy. Unknown keys are preserved by our repository, although the traced vendor constructor does not retain them.

## 2. Real independent storage and full fitted workflow

`ReferenceLocalProfileStore` stores metadata, complete typed classifier and explicit priors/neutral scale together in one SQLite row/transaction. It uses the existing signature fitter, codec and Gaussian inference kernel. It does not replace the independently designed live diagonal-profile trainer or modify acquisition. This is an internal full-covariance research repository, not an application UI integration or an exact Couchbase replacement.

The independent format is version 1 JSON encrypted with CryptoKit AES-256-GCM. Caller supplies a 32-byte key; no vendor keys, salt, models or credentials are required or stored. A fresh random nonce is generated by CryptoKit. Authenticated associated data binds format, profile ID and revision. Metadata UUID must match the identifier. This detects payload/identity/revision alteration, but does not detect restoration of an entire earlier authentic database without an external trusted counter. Compression is deliberately not required in this format; the traced gzip/CBC codec remains comparison-only.

Defaults are our resource policies: 8 MiB plaintext, configurable up to 64 MiB, JSON nesting 32, decoder element bound derived from byte budget, ASCII identifier length <=128, and configurable SQLite busy timeout (default 5000 ms). These are not recovered Cortex parameters. Keys must be retained by the caller across reopen; keychain lifecycle/rotation is not provided by this research repository. Use a private local application directory; WAL must not be hosted on a network filesystem.

SQLite is opened FULLMUTEX/NOFOLLOW with WAL verified from the pragma result, synchronous=FULL, database permissions 0600, and explicit begin/commit/error propagation. Parent paths are resolved with POSIX realpath to support macOS /var aliases while refusing a database-file symlink. IDs are bound parameters. Revision zero creates; later saves require the exact existing revision under BEGIN IMMEDIATE. Connections are serialized within an instance; SQLite coordinates distinct connections. Missing records return nil. Schema-version mismatch, contention, malformed payloads and authentication failure are observable errors.

Before-commit errors rollback. After successful commit, a fault before acknowledgement is reported as committedWithoutAcknowledgement(revision), and recovery sees the committed record. This is distinct from a rollback. The fault hook exists for tests and must not reenter the store.

The vendor body instead performs ordered CouchDriver document saves, stops on the first document error and requests rollback. The transaction guard prevents a subsequent end(true) from re-committing a successfully rolled-back transaction. Outer code returns the document code; direct propagation of begin/commit helper errors is not proved. Cache publication and attribute-file writes are separate, and no cross-file/database atomicity is demonstrated. Our single-row atomic storage is an explicit independent reliability choice.

## 3. Offline recovery qualification

`ReferenceLocalProfileStoreTests` exercises actual signature fitting -> classifier packing -> authenticated disk save -> connection close/reopen -> identical posterior/density outputs. It also exercises two-connection stale revisions, real SQLite writer contention, injected precommit rollback and postcommit acknowledgement failure, wrong keys, revision tampering, byte limits, unknown schema versions and database symlink rejection.

The macOS interrupted-write test launches `/usr/bin/sqlite3` against the real temporary database, stages a corrupt uncommitted replacement, waits for its STAGED acknowledgement, kills that process with SIGKILL, then reopens and validates the previous complete fitted profile and inference. This is a real process termination test; it is not a simulated success callback. It does not establish physical power-loss durability, disk-full recovery, filesystem fault tolerance or target-headset performance.

Reproduce:

```sh
swift test --package-path apple --filter 'ReferenceLocalProfileStoreTests|ReferenceTrainingMetadataTests'
swift test --package-path apple --filter 'Reference|Decoder'
swift test --package-path apple --filter EEGCoreTests
python3 tools/render_capability_matrix.py --check
```

SQLite explains [WAL commit/checkpoint behavior](https://www.sqlite.org/wal.html) and [synchronous settings](https://www.sqlite.org/pragma.html#pragma_synchronous). FULL requests synchronization at commit; actual storage hardware and OS behavior still require separate qualification. Do not copy a live database without its WAL: use SQLite backup or a quiescent closed repository.

## Remaining exact-comparison gates

All ten metadata field names are resolved, but their complete Qt conversions are not. Vendor trained PCA/canonical/Gaussian profile values and matching Cortex outputs are still unavailable. The previously identified embedded salt is excluded and only needed for exact vendor file-key derivation, not this independent repository. Physiological command validity, nuisance rejection and cross-session command reliability require participant experiments; no exact full Cortex parity or production-readiness claim follows from these offline tests.
