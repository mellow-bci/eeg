## Three distinct notions of correctness

1. **File recovery:** authenticated encrypted Parquet reading; damaged-copy negative check.
2. **Device decoder equivalence:** full-channel identical-sample agreement with Cortex.
3. **Physiological/intent validity:** controlled biological evidence and model evaluation.

The first two have concrete evidence for the observed setup. The third is not
established. The hardware test still does not independently establish an analog
calibration against a laboratory voltage source or validate another revision.

## Native decoder direct reference replay (2026-09-15)

The Swift decoder now has an optional qualification export that decodes the archived
BLE notifications and writes its own ADC, voltage and raw-CQ values. It copies only
historical transport annotations after checking index/counter alignment. It does
not copy Python numeric outputs. The existing full-vector comparator then reads
the retained Cortex Parquet table directly.

Eight DecoderTests passed, including this export. The comparison found 15,361
unique full-vector matches out of 15,374 decoded samples; all 15,108 historically
stable samples matched contiguously within their segments. Raw CQ agreed on all
15,361 matches; maximum voltage difference was 0.000237880609347485 µV. The same
13 unmatched startup samples and one startup order reversal remain visible.

Report: `qualification/native-cortex-retest-20260915.json`. This is offline native
decoder evidence, not fresh native Bluetooth acquisition, physiological validity
or mental-command accuracy. Full-vector matching does not independently qualify
timestamps, analog calibration or another headset configuration.

Reproduce with a new output path (existing files are rejected):

```sh
EEG_NATIVE_RETEST_OUTPUT=/tmp/native-retest.jsonl swift test --package-path apple --filter DecoderTests
python compare_paired.py /tmp/native-retest.jsonl archive/current-state/reference-retest/recovered.parquet --output /tmp/native-reference.json
```

The comparison needs NumPy and PyArrow; this run used PyArrow 19.0.1. The native
export is a test/qualification adapter, not a second application recording path.
