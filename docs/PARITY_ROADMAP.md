# Unified EEG application: Cortex breadth and independent roadmap

Checkpoint: 2026-09-15. This roadmap uses the **actual 19,935-line archived symbol table**
at `archive/current-state/local-app-analysis/all-symbols.txt`, demangled locally with
`c++filt` while preserving original line numbers. Links below point to the original mangled
symbols; readable names are abbreviated qualified class/method names from demangling.
A class, linked dependency or symbol establishes presence in this binary's symbol inventory,
not a reachable UI, enabled feature, exact algorithm, valid model, scientific accuracy or
our feature equivalence. Reproducing the category means building and validating our own
capability, not asserting identical vendor results.

The one user flow is **Collect → Review → Analyze → Calibrate → Controlled output**.
SwiftUI on macOS/iOS/visionOS is the application target. One canonical acquisition service
feeds one recording service; analysis and calibration operate on those same versioned
recording/sample contracts. Python utilities remain reference/research implementations and
test oracles; they are not additional user-facing products or alternate hidden pipelines.
Named target services below describe architecture to converge on, not classes already built.

The table below is generated; edit `capability-matrix.json` and run
`python tools/render_capability_matrix.py`. `--check` validates synchronization
and reference locations, not scientific truth or vendor equivalence.

Versioned machine inventory: [`capability-matrix.json`](../capability-matrix.json). Status
values are `discovered`, `understood`, `implemented`, `tested`, `hardware-validated`; each
applies only to its named subset. No row currently claims native hardware qualification.
Independent mental-command workflow implementation is prioritized in
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).

Implementation order: prioritize the independent mental-command workflow
(contract, windows, features, profile training, neutral inference, independent evaluation),
whose first offline Python implementation now exists. Earlier eye/gesture LDA experiments
remain separate and do not establish mental-command validation;
while acquisition/recording qualification proceeds in parallel. Only after both evidence
tracks pass should limited, reversible controlled output be enabled. Additional hardware, model families and enterprise sync extend
the same service contracts. They do not create another setup wizard, recording format or
conflicting source of settings.

Vendor license/subscription checks are intentionally not features to reproduce or bypass.
Our product owns its local capture/export behavior. No runtime depends on unlocking a vendor
app. Model performance and neuroscience claims are governed by
[COGNITIVE_VALIDATION.md](COGNITIVE_VALIDATION.md), transport by
[QUALIFICATION.md](QUALIFICATION.md), and Apple output by
[APPLE_PLATFORM.md](APPLE_PLATFORM.md). “Parity” in this roadmap means accountable coverage
of user needs; it never means inferred equivalence from symbols.
